1. THE ONE IDEA (start here when lost)
--------------------------------------------------------------------------------
Question the whole app answers:

  "Given multivariate spindle-like sensor streams, which cells look unusual
   right now, how healthy are they on a 0–100 scale, and roughly how soon
   should maintenance pay attention?"

If a feature does not improve honest triage, shop-floor language, OPC-UA-shaped
architecture, or manufacturing employer framing, it does not belong. That filter
stops overbuilding (no LSTM-AE, no fake plant integration, no PHM leaderboard
chase in weekend two).

5. HEALTH SCORE. DERIVE IT ON PAPER
--------------------------------------------------------------------------------
Train Isolation Forest on early-life windows only (healthy regime , 
IF_HEALTHY_FRACTION in config). Then:

  s      = decision_function(x)          # higher = more normal
  med    = median(s_healthy)
  mad    = median(|s_healthy - med|)
  z      = (s - med) / (1.4826 * mad)  # robust z-score
  health = clip(85 + 12 * z, 0, 100)

Interpretation you can say out loud:
  "Health ~85 is typical early-life behaviour. Each robust σ below that
   knocks about 12 points off the score."

Late-life windows fall below the healthy score distribution → low health → amber/red.

Status:
  green  if health ≥ 75
  amber  if 50 ≤ health < 75
  red    if health < 50

TTF proxy (not ML):
  ttf_cycles = TTF_MAX * (health/100)^gamma
  with gamma set so health=50 ≈ 40 cycles (see config + ttf.py)


--------------------------------------------------------------------------------
6. PREPROCESS PIPELINE (MULTIVARIATE TIME SERIES)
--------------------------------------------------------------------------------
Per machine, chronologically:

  raw row
    → out-of-range sensors become NaN          (plausibility)
    → record was_missing flags                 (don't erase uncertainty)
    → forward-fill up to 3 cycles              (glitch repair only)
    → remaining NaNs → machine median          (leading-edge gaps)
    → StandardScaler                           (shared fleet scale)
    → sliding windows (30 @ stride 3)
         each window → [mean, std, last, slope] × 6 sensors = 24 features

Missing-value philosophy: short gaps are noise; long gaps are information.
We keep flags even after imputation so a v2 model can use them.


--------------------------------------------------------------------------------
7. MOCK OPC-UA. WHAT IS REAL VS THEATER
--------------------------------------------------------------------------------
Real in this repo:
  - NodeId strings that look like Kepware/TwinCAT browse paths
  - A client façade (browse / read / read_sensors / connection_banner)
  - Values sourced from the sensor replay buffer + published health tags

Theater (intentionally):
  - No listening TCP socket on opc.tcp://… unless you add asyncua yourself
  - No certificates, no PLC, no plant VPN

Why hiring managers still care:
  Manufacturing ML fails at the IT/OT boundary more often than at the model.
  Showing the abstraction proves you know where the dashboard should plug in.
